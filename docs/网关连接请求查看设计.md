## 目标

只有当 GUI 连接（WebSocket 有客户端）时才进行内存存储和数据处理，关闭日志记录时也能通过 GUI 查看请求。

## 修改方案

### 1. 添加 WSHub 连接状态检测方法

在 `api/websocket.go` 中添加：
```go
func (h *WSHub) HasClients() bool {
    h.mu.RLock()
    defer h.mu.RUnlock()
    return len(h.clients) > 0
}
```

### 2. 修改 `proxy/handler.go` - 按需存储

只有当 `wsHub.HasClients()` 为 true 时才存储到内存：

```go
// 只有 GUI 连接时才存储
shouldStore := h.wsHub != nil && h.wsHub.HasClients()

var connInfo *memory.ConnectionInfo
if shouldStore && h.memoryStore != nil {
    connInfo = &memory.ConnectionInfo{...}
    h.memoryStore.Add(connInfo)
}
```

### 3. 修复 base64 问题 - 在序列化时转换

修改 `api/websocket.go` 的 `Broadcast` 方法，在序列化前将 `[]byte` 转为 `string`：

```go
case conn := <-h.broadcast:
    // 转换 []byte 为 string 避免 base64
    dto := toConnectionDTO(conn)
    data, err := json.Marshal(map[string]interface{}{
        "type": "connection",
        "data": dto,
    })
```

### 4. 添加 DTO 转换函数

在 `api/dto.go` 中创建：
```go
type ConnectionDTO struct {
    // 与 ConnectionInfo 相同，但 body 字段为 string
    RequestBody  string `json:"request_body,omitempty"`
    ResponseBody string `json:"response_body,omitempty"`
}

func toConnectionDTO(conn *memory.ConnectionInfo) ConnectionDTO {...}
```

### 5. 修改 `api/handlers.go` - API 返回也用 DTO

`listConnections` 和 `getConnection` 返回 DTO 而非原始结构。

## 效果

- GUI 未连接时：不存储到内存，零额外开销
- GUI 连接时：存储并推送，body 显示为可读文本
- 日志记录独立控制，与 GUI 连接状态无关

## 涉及文件

- `proxy/internal/api/websocket.go` - 添加 HasClients()
- `proxy/internal/api/dto.go` - 新建 DTO 和转换函数
- `proxy/internal/api/handlers.go` - 使用 DTO
- `proxy/internal/proxy/handler.go` - 按需存储逻辑
